# 本机会话来源 v1（v0.4 展示扩展）

这是受限兼容来源，不是官方稳定 API，不宣称与宠物完全一致。既有本机验证对象为 `/Applications/Codex.app` 26.1013.40934，arm64 / macOS 27.0.1；最低部署目标仍为 macOS 14，未在最低系统和 Intel 实测。

## 数据目录配置（v0.7.3 起）

GUI、原生探针和 GUI 的 `--diagnose` 共用 `FeedConfiguration`。没有 `CODEX_HOME` 时读取当前用户 `~/.codex`；显式设置必须是非空、无 NUL 的绝对目录。空值、相对路径、`~` 和 `file://` 字符串均报 `invalidConfiguration`，不静默回退。目录不存在时后续读取报 `missingDatabase`，不创建目录或数据库。

环境变量必须传入实际启动的进程；Finder 启动的应用不会自动继承终端中临时设置的变量。例如可显式执行：

```bash
CODEX_HOME=/absolute/codex-home ./build/CodexIsland.app/Contents/MacOS/CodexIsland
CODEX_HOME=/absolute/codex-home ./build/CodexIsland.app/Contents/MacOS/CodexIslandProbe
```

解析规则只选择来源，不扩大 sessions 路径边界。显式外部状态文件与演示仍独立于此配置。`--diagnose` 报告配置是否有效和是否使用覆盖，不输出目录，也不把配置有效当作数据库可读。已发布 v0.7.2 仍固定读取 `~/.codex`。

## 读取内容与范围

- `~/.codex/state_5.sqlite`：选择线程标识、会话名称（优先 name，空缺时回退 title）、rollout 路径、归档及根会话标记。
- `~/.codex/thread_history_1.sqlite`：选择最新回合标识、状态、事件起点和结束时间，以及当前回合最新 item 的类型、状态和活动时间；不提取命令正文。
- `~/.codex/sessions/`：只对正在运行的回合，从其事件起点增量读取；保留事件类型、工具名称、调用标识和回合标识；异步问答额外提取问题数量、accepted 标记及回答中的问题标识，不保留问题文字、回答或普通工具输出。

连接使用 SQLite READONLY，附加数据库显式 `mode=ro`，不写 Codex 配置、数据库、事件、已读记录或凭据。查询最多 10000 条记录、最多 32 个并行活动；单次 SQL 预算约 300ms，锁等待 100ms；每个运行回合每次读 256KiB。已发布 v0.7.3 的单行上限为 1MiB；之后的未发布源码改为下述有界 JSON 投影，不再按整行正文长度拒绝有效事件。问答跟踪最多保留 1024 项待处理请求、每个调用标识最多 512 UTF-8 字节；已全部回答的异步请求立即移除。超限回退为数据库证实的 running，并报告 caughtUp=false，不推断等待。超过能力时明确降级。文件必须位于 sessions 内，解析符号链接后再次校验。

v0.6.2 将最新 item 的关联子查询置于 CASE 内，仅在 `inProgress` 时求值；单靠 LEFT JOIN 外层状态条件不能保证跳过历史记录排序。已完成回合直接提供 idle 与标题，不扫描旧工具记录。查询超时单独报告为 `queryTimedOut`。应用的系统日志仅记录固定错误类型及恢复事件，不含标题、路径、提示词或工具载荷；可用 Console 按 subsystem `dev.water.codex-island` 查看来源与快照校验失败的区别。

只覆盖本地历史索引中存在最新回合记录、未归档、根路径为 `/root` 或旧版 NULL 的会话，同时排除 source 元数据带 subagent 的系统子任务，避免没有路径标记的 guardian 被误计。后台子代理不单独计数。没有回合投影的线程、远端 / 云端聊天不在覆盖范围；本机来源通过悬停帮助与 VoiceOver 标明；右侧为宠物，演示 / 外部来源在状态行保留文字标记。内部快照的 `isComplete` 仅指此明示范围，不能解释为宠物的全部活动集合。

## 状态映射

| 证据 | 浮窗行为 | 边界 |
| --- | --- | --- |
| 最新回合 `inProgress` | 工作中 | 不因长时间无事件而自行结束 |
| 当前回合显式 `request_user_input` 调用尚无对应输出，事件已追平 | 需要你 | 目前未证明覆盖系统审批、所有 MCP 询问与所有输入方式 |
| 同步问答对应调用输出 | 恢复工作中 | 按调用标识配对，其他工具输出不解除等待 |
| 当前回合 `request_user_input_async` 且工具输出 `accepted=true` | 需要你，介入色脉冲 | 受理回执不等于回答；支持 functions 前缀 |
| 用户结构化 `send_user_message_question_reply` 中匹配的 questionItemId | 对应问题解除，全部回答后恢复工作中 | 按工具名 / call ID / 问题下标配对；部分回答保留其余问题 |
| 来源启动后产生的最新回合 `failed` | 工作受阻 | 历史失败不会在启动时重播；没有桌面已读清除机制，下一回合替换该状态 |
| `completed` / `interrupted` | 进入 idle，保留会话标题与等待动画 | Codex 运行时不隐藏；不产生“待查看”，不伪造未读 |
| 缺数据库、未知枚举、字段漂移、读取失败 | 暂无法同步 / 状态暂不可用 | 不将错误当空闲 |

正在启动的长回合可能需要数次刷新才能追平事件；追平之前只显示数据库证实的“工作中”，不从半条记录或不完整事件推断等待。Codex 退出时隐藏并清空游标；重新出现后重新观测。回合变更、文件更换、截断和来源重置均清空旧等待。

## 事件失败与恢复（v0.7.3 起）

单个会话的事件读取或解析失败后，清除其不完整问答信号，保留数据库证实的工作状态，并显示“同步受限”。重试按会话、回合、rollout 路径和回合起点隔离，使用单调时间，依次等待 1、2、4、8、16、30 秒，之后最多每 30 秒一次；等待期间不重新打开事件文件。健康会话继续处理，仍可显示有完整证据的问题等待。

每次重试从该回合起点重新建立完整事件语义；成功读取部分数据不清除既有失败次数，完整追平才视为恢复。不会跳过坏记录并伪称追平。已发布 v0.7.3 仍有 1 MiB 单条事件限制；之后的未发布源码使用下述有界解析，不能将其与旧安装包混淆。文件修复、替换或截断在下一次重试时检查，最长需等当前 30 秒退避；新回合、数据库中的路径 / 起点变化立即清除旧退避。完成回合移除游标与退避记录，避免长期累积。

菜单栏“重新同步状态”清除来源游标和退避并重新观测，独立于“重新同步宠物与时长”。旧读取的迟到结果不能覆盖手动重置后的状态。普通增量未追平显示“同步中”；事件读取失败显示“同步受限”，不把它们当作完整来源不可用或已空闲。

原生探针新增 `degradedThreads`（仍未完整恢复的事件源数量）和 `retryingThreads`（当前正在退避的数量）。这两个计数只对应活动根会话，不包含标题、路径或载荷。数据库读取失败继续使用独立固定错误类别。GUI 系统日志只在事件源进入降级 / 恢复时记录固定信息，不逐次轮询刷屏。

## 大事件有界解析（v0.7.3 之后的未发布源码）

事件文件按每源每次 262144 字节增量读取，不在内存中累积完整 JSONL 行。`RolloutJSONLProjection` 逐字节校验完整 JSON、UTF-8、转义、数字和容器结构，只保留状态、工具调用标识、问题数量、受理标记与结构化回答标识；普通工具正文、问题标题和答案不保留。必要的 JSON 字符串内嵌层同样增量解析，字段顺序不影响语义。

有效记录中的无关正文超过 1 MiB 时可跨多次刷新继续读取。只有换行到达、该记录完整校验通过后才提交对应事件；半行仍显示同步中。损坏、关键字段重复或超出语义 / 结构预算时继续退避，不跳过后宣称已追平。同步问题对应的普通输出不会因为无关 `output` 格式而触发异步问答解析。

预算：每层 JSON 最大深度 64；状态 / 调用标识最多 512 UTF-8 字节；累计保留投影最多 1 MiB（另有固定解析栈、容器元数据、读取缓冲和有界编码临时副本）；每条消息的 content 与结构化回答数组最多 1024 项；问题标识编码最多 4096 字节。既有最多 1024 待处理调用、每个异步调用 1～32 个问题的约束保持不变。整行总长度不限不等于内存不限，也不表示任意结构都可接受。

游标在新回合、文件更换或截断后重建；部分记录不留下可确认的等待。公共单事件解析接口完整验证成功后才提交状态，异常不能造成部分等待状态变更。测试使用合成大记录、损坏 / 部分输入、边界与问答配对，不把正常时刻的真实探针结果当作旧故障已恢复的证据。

## v0.7.1 问答与审批补充

本机真实记录确认异步问答工具的调用立即收到 `{"accepted":true}`，稍后才出现 user message 的结构化回答。旧解析器只支持同步问答，导致“问题”卡片不触发等待；现已区分两种生命周期。只在已识别调用上解析受理标记，只对用户结构化回答解析问题 ID；普通工具输出和未匹配文字不能解除等待。回合结束 / 中断、新回合、来源重置清除旧等待。已结束回合中仍保留的异步问题目前不跟踪，避免重放历史卡片。

桌面真实审批队列仍未从本机历史取得。独立 IPC 客户端本次仍只有握手 / following 回执，没有业务快照；未冒用客户端身份或请求接管。不能根据提权参数、guardian 自动审查或工具长时间运行推断需要用户批准。

可选 ApprovalUIObserver 在用户开启并授予系统辅助功能权限后，仅遍历 Codex 窗口角色、子节点及启用按钮的标题 / 描述，以小组内成对“允许 / 拒绝”固定中英文标签判断。它不读取 AXValue，不执行 AX action，不保存聊天；权限本身具有更广泛的能力，因此默认关闭。每次遍历限制 2500 节点、深度 36、约 150ms，并跳过最小化窗口。缺少权限或读取失败时回到本机会话来源，不猜测待审批。

该观察不提供可靠会话 ID，检测到审批时第一行显示 Codex、第二行“等待批准”，优先使用介入脉冲；不会把审批随意归到当前标题。关闭后立即清除，异步读取的迟到结果不能重新开启它。可识别标签、显示树结构及预算都有兼容限制；真实审批仍待用户授权后现场验收。

## 本机证据与未验收项

最终过滤规则下，本机探针观测 `trackedThreads=173`、`activeThreads=1`、状态 running，增量事件可以追平。探针只输出数量、状态和能力标记，`supportsUnread=false`、`petParityVerified=false`。

初轮仅按路径过滤时记录过 192/193 条索引及 1/2 项活动波动。核对发现系统子代理可能没有子路径，故已增加来源过滤并回归测试；这些旧计数不再作为并行根会话证据。本轮没有为验证创建或操控其他聊天。初轮 `time -l` 输出约 31.92s 墙钟、0.08s user / 0.07s sys；由于执行沙盒拒绝 `kern.clockrate`，计时工具最终以错误退出，没有取得完整资源报告，不能作为最终整应用性能验收。

v0.4 普通 Release 应用已启动；原生 AX 与截图确认第一行为桌面会话名称，第二行为“思考中 / 已运行命令”等当前活动，标记“本机”。连续帧不同且 AX 文本未变化，确认运行轮廓持续变化。v0.3 已执行岛体按钮点击。尚未验证跨 Space、最小化恢复与从其他前台应用跳转的全部组合。

自动化验证：33 项通过，覆盖桌面会话名称优先于首条提示词、旧快照兼容、细分命令活动、idle 标题保留与常驻、命令失败不终止整轮，以及工作 / 完成、并行根会话 / 子代理排除、显式问答配对、跨回合隔离、部分行、历史失败、未知协议、丢失数据库、只读数据库未改变，以及 rollout 路径边界。不是完整真实场景验收。

待验证：真实等待审批、真实问答解除、真实失败恢复、休眠唤醒、Codex 重启、账号切换、长任务 / 多主机范围及完整宠物一致性。数据库没有独立的会话存活心跳；异常退出遗留的 inProgress 记录可能需要后续兼容处理，不能据此宣称全局实时状态准确。

## 诊断

```bash
./build/CodexIsland.app/Contents/MacOS/CodexIslandProbe
./build/CodexIsland.app/Contents/MacOS/CodexIslandProbe --watch 30
python3 Scripts/probe_desktop_ipc.py
```

原生探针不创建 NSApplication，可在终端或当前开发沙盒中运行，不依赖 Python。Python 探针仅用于诊断订阅兼容性验证，会初始化客户端并发送订阅 / 取消订阅消息，不发送聊天或审批；正式浮窗不启动 Python，也不重复尝试未验证的 IPC 协议。
