# 性能与稳定性验证

## 实现中的预算

- 正常来源约每 500ms 轮询；来源 actor 负责磁盘与 SQL，UI 不同步执行数据库查询。系统通知与轮询刷新合并，取消 / 休眠后不提交迟到的来源结果。
- SQL VM 截止预算约 300ms，锁等待 100ms，最多 10000 个会话 / 32 个活动。不是整次刷新绝对时限；文件 I/O 和系统调用不受 SQL VM 预算约束。
- 未发布源码每个活动每次最多读取 256KiB，以流式投影替代完整行累积；保留投影最多 1MiB，每层 JSON 深度最多 64，另有固定栈 / 容器元数据、读取缓冲与有界编码临时副本。普通正文不随行长累积。待处理问答最多 1024 项、调用 ID 最多 512 UTF-8 字节。已回答的异步记录即时移除。v0.7.3 及以前的完整行 / 待处理缓冲仍限 1MiB。
- 外部快照仅接收普通文件，256KiB 上限；非阻塞打开后检查描述符，FIFO 不等待写入端。
- ASAR 头最多 16MiB、JS 成员默认最多 32MiB、候选最多 8 个、所选图片最多 16MiB。不执行 JS；异常动画时长在乘法前限界。
- 宠物先检查图片尺寸再解码，一次缓存 96×104 动作帧；切帧不读盘，休息时不刷新宠物帧。轮廓最高约 30fps；减少动态效果、隐藏和休眠时暂停相关视图工作。

## 可复现的合成基准

```bash
CODEX_ISLAND_BENCHMARK=1 ./Scripts/test.sh -c release --filter syntheticFeedPerformance
```

使用临时数据库及合成 ID，不访问真实 Codex 数据。创建 1000 个已结束线程和 100000 条历史 item，并添加线程 / 回合索引；预热一次后各采 30 次，第二组增加 32 个已追平的活动线程。最后独立测量 10000 次异步问答生命周期。测试检查结果正确性，不用易抖动的固定耗时阈值阻断 CI。

2026-10-22，arm64、Swift 6.4、macOS 27.0.1、Release：

| 场景 | P50 | P95 | 最大值 |
| --- | --- | --- | --- |
| 1000 idle / 10 万历史 item | 7.876ms | 8.393ms | 8.750ms |
| 上述历史 + 32 active，事件已追平 | 25.520ms | 32.781ms | 45.240ms |

10000 次异步问答、共 30000 个事件解析合计 543.204ms。该数字含合成事件构造，排除了数据库创建和构建时间；SQLite 两组排除了冷启动。它不代表大量增量事件积压时的刷新耗时，也不代表真实数据库索引 / 数据分布、UI、GPU 或内存基线。

## 未发布流式解析的本机复测

2026-10-23，Apple Silicon、macOS 27.0.1、Swift 6.4、Release，使用相同合成基准命令：

| 场景 | P50 | P95 | 最大值 |
| --- | --- | --- | --- |
| 1000 idle / 10 万历史 item | 7.981ms | 8.639ms | 8.694ms |
| 上述历史 + 32 active，事件已追平 | 27.642ms | 40.665ms | 66.264ms |

10000 次异步问答、30000 个事件共 1451.635ms。该路径现在多一层完整流式语法校验与有界投影编码，较上面的历史 543.204ms 记录增加了纯解析成本；这不是同一时刻的对照实验，也不代表整应用 CPU / 能耗比值。大正文的收益是保留内存不随原始行长度增长，并能继续追平合法事件。新增反例检查单次 256 KiB 读取、投影保留预算及大正文前后的问答语义，不使用易抖动的时间阈值代替正确性验证。

整应用 30 分钟 / 工作日基线仍待验收；持续多个活动源同时积压时的 CPU / 内存 / 唤醒不能从这些已追平样本推断。

## 整应用验收流程

构建 Release，使用活动监视器或 Instruments 对指定 CodexIsland PID 观察 30 分钟，分别记录 idle、working、needsInput、关闭动态效果、隐藏岛和关闭 Codex 的 CPU、物理内存、唤醒次数与能耗。记录硬件、系统、Codex 版本和采样窗口；比较同一进程的初期 / 稳态 / 末期，不将编译器的内存当应用内存。

还需验证睡眠唤醒、锁屏解锁、Codex 重启、显示器热插拔、全屏 / Space 切换及长回合。性能问题报告只附聚合指标和固定错误类型，勿上传会话内容。

上述合成基准属于 v0.7.2 的历史结果；30 分钟整应用、GPU / 能耗与最低系统验收未完成。

v0.7.2 之后的源码对坏 JSONL / 超长行 / 事件 I/O 失败增加按会话 / 回合隔离的单调时钟退避，间隔为 1、2、4、8、16、30 秒，上限 30 秒；退避期间不重开该事件文件，数据库查询和其他健康会话仍正常处理。重试完整追平后才清除失败次数；单次成功读到部分数据不重置预算。持久损坏仍可能无法追平，此时保守显示同步受限，不跳过损坏记录。新回合和手动状态同步可立即重置，文件修复在下次重试时检查。详见 [来源恢复行为](local-session-source.md)。

文件描述符相对路径防竞态、ASAR 树深度与 parser fuzzing 仍属于后续加固范围。本次恢复策略的夹具通过不能代替整应用性能和真实桌面验证。


## 整应用聚合采样工具

未发布源码提供 `Scripts/sample_process.c`，基于系统 `proc_pid_rusage` v4 计数，不读取命令行、会话、路径或堆栈。对已经确认的应用 PID 执行：

```bash
xcrun clang -O2 -Wall -Wextra -Werror Scripts/sample_process.c -o /tmp/island-sample
/tmp/island-sample APP_PID 1800 10 > /private/tmp/island-private-samples.jsonl
```

输出包含单调墙钟、累积 user/system CPU 纳秒、physical footprint/RSS 字节、interrupt/package-idle 唤醒及系统 billed-energy 原始计数。CPU 从 proc_pid_rusage 的 Mach 刻度按本机 mach_timebase_info 转换，JSON 同时记录换算比例；不能直接把原始刻度当纳秒。采样器须以本机架构编译运行：Rosetta 的虚拟时基与系统进程计数不同，因此转换执行会明确失败且不输出样本；无需关闭 Rosetta 或改变目标应用。首尾相减得窗口增量；CPU 百分比以增量 CPU 秒除墙钟秒 ×100，100% 表示一个 CPU 核。能耗计数不当作焦耳或活动监视器 Energy Impact；不可读或始终为零时标记无法取得，不推断零能耗。原始样本仅留本机，不进入 Git 或应用包。

分别观察 idle、running、needsInput、关闭动画、隐藏、Codex关闭；记录同一 PID 的初期 / 稳态 / 末期与屏幕是否遮挡。演示 UI 不包含真实磁盘来源，合成来源也不代表真实 Codex 工作日使用。该工具本身与短时 smoke 不能替代 30 分钟 / 工作日完成证据。

采样器的独立校准检查：

```bash
python3 Scripts/test_process_sampler.py
```

该检查只启动一个临时CPU工作子进程，把采样器的CPU增量与子进程自身的POSIX process_time_ns对照，另外验证参数与真实间隔。旧实现直接输出Mach刻度，在本机125/3时基下将CPU低估约41.67倍；修复前校准明确失败，修复后通过。早期未校准smoke的CPU百分比无效，不用于性能预算。持续采样若仍使用旧二进制，必须保留原始计数和时基另行换算，不能混用新旧单位。
